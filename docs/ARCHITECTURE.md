# Architecture

godotai is a small, auditable agent (stdlib-only Python) around one idea —
**the model is never trusted; the engine is.** Every claim of success has to come from
running the pinned Godot 4.7.2-stable binary headless, and every API the model uses can be
checked against the class database *generated by that same binary*.

A second rule follows from the owner's goal (an AI that is *theirs*, not a vendor's):
**the model behind the agent is the user's own server by default, and what those weights are is
stated plainly and enforced** (`model_identity.py`, `docs/MODEL.md`). A vendor model can be plugged
in, but only labelled as such, and only `eval compare` — never a sentence in the UI — may say how two
models compare.

```
 user task ──► Agent.run()          ◄── CLI `run` / `plan`, or the browser chat (`chat/`) over the same loop
               │  THINK  (read project, knowledge_search, api_lookup) ── read-only tools only
               │  PLAN   submit_plan → validate_plan()              ── schema + version + path checks
               │  GATE   human approves / rejects with feedback     ── CLI prompt or --yes
               │  ACT    write_file / edit_file / run_command …     ── every call needs step_id ∈ plan
               │  VERIFY godot_verify → verify_project()            ── real engine: import, check-only, smoke test, API lint
               └─ REPORT RunSummary + .godotai/runs/<ts>.json

 model calls ──► providers/openai_compat.py ──► YOUR server (vLLM / Ollama / llama.cpp, default http://127.0.0.1:8000/v1)
                 providers/anthropic.py     ──► vendor API, opt-in, must be declared [model].kind = "vendor_api"

 .godotai/runs/*.json ──► dataset extract ──► data/*.jsonl ──► training/train_qlora.py ──► LoRA adapter ──► vllm --enable-lora
                                                  (only engine-verified runs; thinking dropped; secrets redacted)      (same name "godotai")
 evals/tasks/*.json ──► godotai eval run|score ──► evals/results/*.json ──► godotai eval compare   (engine + structural checks,
                                                                                                     common tasks only, no model judge)
 browser ──HTTPS──► Cloudflare Access ──Tunnel──► cloudflared ──► chat/server.py (re-verifies the Access JWT) ──► the same Agent
```

## Modules

| Module | Responsibility |
| --- | --- |
| `config.py` | Loads `godot.toml`; `EngineConfig` derives every official asset name/URL from `version`+`release`; env overrides (`GODOTAI_*`); strict — unknown keys are errors. `AgentConfig.endpoint` resolves the model URL (explicit `base_url` → `GODOTAI_BASE_URL` → `OPENAI_BASE_URL` → api.openai.com only with `OPENAI_API_KEY` → the local private default) and `private_endpoint` says whether that is the user's own server. `Config.__post_init__` runs `model_identity.check_consistency`. |
| `model_identity.py` | `ModelIdentity` (`[model]` in `godot.toml` / `GODOTAI_MODEL_*`): `kind` ∈ open_weight_deployment · fine_tune · from_scratch · vendor_api, base model + licence, adapter, serving. `describe()` yields the bilingual disclosure the UI and `doctor` print (incl. "not trained from scratch", "not yours"); `check_consistency()` refuses a vendor endpoint labelled as the user's model, a fine-tune without an adapter, a from-scratch claim without a training report. `quality_claim` is always `None`. |
| `godot.py` | `Godot` wrapper: finds the binary, **refuses any version other than the pin**, runs `--import`, `--check-only`, `--quit-after`, `--script`, `--export-debug/--export-release`. |
| `verify.py` | The verification pipeline → `VerificationReport` (markdown + JSON). `classify_output()` turns raw engine output into errors/warnings, ignoring known headless noise (root warning, RID leaks at forced quit, dummy renderer). |
| `planner.py` | Plan schema (strict JSON schema), `validate_plan()` (correct engine version, sequential S1..Sn ids, safe relative paths, no secret files, a final `verify` step, mandatory `godot_import`/`check_scripts`/`smoke_test`), persistence to `.godotai/plan.json` + `PLAN.md`. |
| `tools/base.py` | Tool registry + **policy**: mutating tools return `POLICY:` errors before approval, need a known `step_id` during ACT, and are frozen when DONE. Handler exceptions never crash the loop. |
| `tools/fs.py` | Workspace-sandboxed `list_files`/`read_file`/`write_file`/`edit_file`/`delete_file`; refuses path escapes, secret files (`*.keystore`, `.env`, …) and writes into `.godot/`; converts 4-space indentation to tabs in `.gd`. |
| `tools/godot_tools.py` | `godot_info`, `godot_verify`, `godot_check_script`, `godot_run_headless`, `godot_export`, allow-listed `run_command` (no network binaries; secrets stripped from the child environment). |
| `tools/github_tools.py` | `github_create_repo`, `github_push_project`, `github_build_apk`, `github_build_status` over the REST API + git (token via `GIT_ASKPASS`, never in URLs). `sync_workflow()` copies `build-android.yml` into game repos with the pin applied. |
| `tools/knowledge.py` | Progressive-disclosure knowledge base: only `knowledge/INDEX.md` bullets are in the prompt; `knowledge_search`/`knowledge_read` pull sections on demand. |
| `apiref.py` | **Engine-generated API index**: runs the pinned binary with `--doctool`, parses the ClassDB XML (classes, inheritance, methods + defaults, properties, signals, constants/enums, annotations, deprecated/experimental flags) into a cached JSON index; exact + case-insensitive lookup with inheritance, suggestions for typos and Godot-3 names, full-text search, and a **lint** that flags Godot-3 idioms and unknown classes/methods in `.gd` files. |
| `tools/apiref_tools.py` | Read-only tools `api_lookup`, `api_search`, `api_lint` exposed to the model (allowed in every phase). |
| `evals.py` | Task bank runner/scorer: engine verification + structural checks (required files, regexes, typing ratio, API-lint errors, smoke test, refusal). Never a model-as-judge. `compare_models()` groups `evals/results/*.json` by the model that produced them and tallies only tasks both have results for → `NO EVIDENCE` without common tasks, an explicit "task-specific observation" caveat below three. |
| `dataset.py` | Turns run logs into SFT trajectories: keeps only engine-verified runs (or repair runs on request), normalises Anthropic/OpenAI transcripts, drops thinking blocks and harness scaffolding, **redacts secrets**, de-duplicates. |
| `secrets.py` | Token-shape detection (Anthropic/OpenAI/GitHub/AWS/Google/Slack/Kaggle/Cloudflare/HF, PEM blocks, bearer tokens, credential assignments), redaction, tree scan (`scripts/secret_scan.py`, also a CI step). |
| `providers/anthropic.py` | **Opt-in vendor reference, not the product** (the loader requires `[model].kind = "vendor_api"`). Claude Messages API tuned for **Claude Fable 5.1**: `tool_choice: auto` only, no `thinking` param/`temperature`, `output_config.effort`, constant `system`+`tools` prefix with `cache_control`, thinking blocks replayed verbatim, `stop_reason: refusal` handled; opt-in betas: per-message `act_effort`, `task_budget`, progress updates, turn-scoped system messages, prefix-binding diagnostics; Cloudflare AI Gateway pass-through/BYOK headers. |
| `providers/openai_compat.py` | **The default.** Any OpenAI-compatible chat-completions server (vLLM, Ollama, llama.cpp, OpenRouter, Cloudflare Workers AI) → the user's private open-weight model served as `godotai`, or the fine-tuned adapter from `training/` under the same name. Tool calls follow the OpenAI schema (vLLM: `--enable-auto-tool-choice --tool-call-parser hermes` for Qwen2.5). |
| `providers/cloudflare.py` | Builds AI Gateway / Workers AI URLs and headers from **environment variable names only** (`CF_ACCOUNT_ID`, `CF_AIG_GATEWAY`, `CF_AIG_TOKEN`, `CLOUDFLARE_API_TOKEN`). |
| `agent.py` | The loop above; append-only transcript; nudges the model if it stops without a plan or a passing verification (batching nudge, long-output note); logs progress updates/API notices; hard limits `max_iterations` / `max_verify_rounds`. Optional hooks: `on_tool(call, result)` (structured tool events) and `should_stop()` (cooperative cancellation, checked before each model turn and after the gate) — the CLI uses neither, the chat uses both. |
| `chat/` | **The place you talk to the AI.** `session.py`: one `Session` per game folder — runs `Agent.run()` in a daemon thread, turns `on_text`/`on_progress`/`on_tool`/`approve` into an ordered, replayable event log, persists history to `.godotai/chat.jsonl`, exposes approve/reject/cancel/verify and a sandboxed read-only file view (same `safe_path`/secret filters as the model's tools). `status.py`: engine + model readiness — for the private default it probes `GET <base_url>/models` (1.5 s timeout, 5 s cache, `GODOTAI_SKIP_MODEL_PROBE=1` → "not probed") and reports reachable / unauthorized / served names / configured name present, plus the identity disclosure; hints name the exact `vllm serve` / Ollama / compose command. `server.py`: stdlib `ThreadingHTTPServer` (default `127.0.0.1:8765`) serving `static/` (Arabic RTL page, quick game prompts, identity card, hosting badge; no inline script, strict CSP) and a small JSON + SSE API; loopback-only unless a token **or** Cloudflare Access verifier is given; Host/Origin guards with `--public-host` allow-list; `/healthz` is the only unauthenticated route. `access.py`: Cloudflare Access JWT verification — `Cf-Access-Jwt-Assertion` header or `CF_Authorization` cookie, JWKS from `<team>.cloudflareaccess.com/cdn-cgi/access/certs` (cached, refreshed on unknown `kid`), RS256 with stdlib arithmetic, issuer/audience/exp/nbf/iat with skew; raw tokens never appear in errors. No framework, no build step; hosting is the user's choice (`deploy/cloudflare/`). |
| `install.py` / `android.py` / `scaffold.py` | Engine installer (SHA-512 verified), Android SDK + editor settings + debug keystore, project scaffolding from `templates/`. |
| `__main__.py` | CLI: `doctor`, `install-godot`, `setup-android`, `new`, `verify`, `export`, `plan`, `run`, `chat`, `apiref`, `eval`, `dataset`. |
| `training/` , `scripts/` | Optional QLoRA fine-tuning of the open-weight base on verified trajectories (`train_qlora.py`, Kaggle script kernel + `kaggle_push.py`), repo secret scan, and `cloudflare_setup.py` — the four Cloudflare API calls (Access app → tunnel → ingress with *Protect with Access* + 404 catch-all → proxied CNAME) behind an injectable transport, `--dry-run`, `.env` written with mode 0600, tunnel token never printed. |
| `deploy/cloudflare/` | `compose.yml` (chat with no published port + `cloudflared` + exactly one model-server profile: vLLM base / vLLM + LoRA / Ollama), `env.example` (placeholders only), README (Arabic-first). Nothing in it is deployed by the repository. |

## Design decisions (and why)

1. **Version pin as data, not code.** `godot.toml` is read by the agent, installer, Dockerfile, CI and templates.
   Changing the pin = edit one file + add the official `SHA512-SUMS.txt`. Tests (`tests/test_infra_sync.py`)
   fail if the workflows drift from the config.
2. **Policy in code, not in prose.** Prompts ask the model to plan first; the registry *enforces* it. A model
   that ignores instructions still cannot write a file before approval or outside the approved plan.
3. **Constant prefix.** Claude Fable 5.1 binds thinking blocks to the `system`/`tools` prefix and requires an
   append-only history. We therefore keep one tool list for the whole run and gate by phase instead of
   swapping tool sets (which is also what makes prompt caching effective).
4. **Engine-backed verification, not self-assessment.** `--import` catches malformed `.tscn`/`.tres` and
   missing resources, `--check-only` is the engine's own static analysis for GDScript, and the smoke test
   (`tests/smoke_test.gd`, a `SceneTree` script) drives the real main scene for N frames and asserts state.
5. **Human gate with feedback.** Rejecting a plan sends the reviewer's text back to the model and returns
   to the PLAN phase. Mid-execution re-planning is allowed but audited (`.godotai/plan.json` is rewritten).
6. **Secrets never touch files or the model.** Keystore paths/passwords come from the
   `GODOT_ANDROID_KEYSTORE_*` environment variables Godot reads natively; the model cannot read or write
   `*.keystore`, `*.jks`, `*.pem`, `.env`; `run_command` children get a scrubbed environment; the GitHub token
   is passed via `GIT_ASKPASS`.
7. **Stdlib only.** No SDKs, no framework lock-in: the whole agent is readable in one sitting and runs in the
   minimal Docker image. Open-source agent frameworks (OpenHands, Aider, SWE-agent, Goose, OpenCode, Cline)
   were evaluated and are far more general than needed; their generality is exactly what a single-purpose
   agent should *not* carry. See RESEARCH.md. (The ML stack for `training/` is imported lazily and only there.)
8. **Ground the model in the engine's own class database, not in its memory.** Hallucinated or Godot-3 APIs
   are the most common failure of LLMs on Godot 4. The index built from `--doctool` gives exact signatures
   (`api_lookup`), a search (`api_search`) and a lint that runs inside verification and `godot_check_script`.
   Lint on user-defined symbols is a warning; only unambiguous Godot-3 idioms are errors.
9. **Borrow *how* Claude Fable 5.1 is driven, not the model itself.** The user wants a specialised Godot AI
   that is *theirs*, with Fable 5.1 as the reference for good reasoning. What the docs attribute that quality
   to — adaptive, self-checking thinking scaled by effort; reasoning at every tool boundary; long-horizon
   budgets; an append-only, cache-friendly harness — is mapped onto config switches and loop behaviour
   (RESEARCH.md §3.3). Any provider gets the same harness; the user's own open-weight server is the default,
   the vendor model is an opt-in reference, and only the eval bank (`eval compare`) says how they compare.
10. **Say what the model is; enforce it; claim nothing else.** `[model]` records the *kind* of weights
    (private open-weight deployment today; the user's fine-tune once an adapter exists; from-scratch only with
    evidence; vendor API when a vendor is used). The loader rejects contradictions (a vendor endpoint labelled
    as the user's model), the UI prints the same disclosure verbatim, and no code path can emit a "better
    than X" sentence — the comparison exists only as engine-scored `eval compare` output on common tasks.
11. **Public website = the same server behind Cloudflare Access, verified twice.** Cloudflare authenticates
    the visitor (e-mail allow-list) before the tunnel; the chat re-validates the Access JWT on every request
    (page, assets, API) as the Cloudflare docs ask, so a misconfigured tunnel or a leaked origin address still
    yields 401. No inbound port, no shared token in URLs, tunnel token only in an untracked `.env` (mode 0600),
    `/healthz` the single unauthenticated route (returns `{"ok": true}` and nothing else).
12. **Data flywheel with a free oracle.** Every successful run is an engine-verified trajectory; `dataset
    extract` filters, cleans and redacts them; `training/` fine-tunes; `eval` measures with the same engine.
    GPUs/TPUs (Kaggle) are batch resources for that step only — they never sit in the agent's request path.
13. **The chat is a shell around the agent, not a second agent.** `chat/` adds no prompt, tool or policy of its
    own: it constructs the same `Agent` with the same registry and feeds it the same task string a CLI user
    would type, so the gate, the step-id policy and the engine verification are identical whether a game is
    requested from a terminal or from the browser. Two hooks (`on_tool`, `should_stop`) were the only agent
    change needed. It is local by default (loopback) because it can write files and run the user's model; a
    public instance is the user's own deployment (`deploy/cloudflare/`) — the repository hosts nothing.

## Data written to a game workspace

```
<workspace>/
  .godotai/plan.json, PLAN.md         the approved plan (audit trail)
  .godotai/last_verification.md       last engine report
  .godotai/runs/<timestamp>.json      full transcript + usage + verification state (git-ignored by default)
  .godotai/chat.jsonl                 chat history (one JSON event per line) when the project was driven from the chat UI (git-ignored)

deploy/cloudflare/.env                 written by scripts/cloudflare_setup.py (mode 0600, git-ignored): public host, team domain,
                                       AUD, tunnel id and the tunnel token — the only place that token may exist
  .github/workflows/build-android.yml added by github_push_project if missing
  .gitignore                          added by github_push_project if missing
```

## Extending

- **New template:** add `templates/<name>/` with `project.godot`, `export_presets.cfg`, `tests/smoke_test.gd`,
  using the `__GAME_NAME__`, `__PACKAGE__`, `__GODOT_FEATURE__`, `__GODOT_TAG__` placeholders.
- **New knowledge:** add a `.md` under `knowledge/` and a bullet in `INDEX.md` (tests enforce the index).
- **New tool:** register it in `godotai/tools/*.py` with `mutating=True` if it changes state — the policy
  layer then applies automatically.
- **New eval task:** add `evals/tasks/<id>.json` (prompt, expected files/regexes, typing ratio, smoke test);
  `python3 -m godotai eval score --task <id> --project DIR` scores an existing project without a model.
- **New engine version:** change `godot.toml`, add `engine/checksums/<tag>/SHA512-SUMS.txt`, review
  `knowledge/` against the new release notes, run `python3 -m godotai doctor`, `apiref build --force`
  (the index is keyed by engine tag) and the test suite.
- **New base model / your adapter:** change `[model].base_model` + `base_license` (read its model card — not every
  Qwen size is Apache-2.0; Llama has its own licence), or set `kind = "fine_tune"` + `adapter`; serve it under the
  same name (`--served-model-name godotai` / `--lora-modules godotai=…`); `tests/test_model_identity.py` keeps the
  docs and config consistent; `eval compare` tells you whether it was an improvement.
